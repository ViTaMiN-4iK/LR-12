# Промпты для генерации тестов (задание 7, Лаб. 12)

Используйте как шаблоны для ИИ; после генерации прогоняйте `python -m pytest tests/ --cov=app --cov-fail-under=90`.

## Шаблон 1 — «счастливый путь» API

Ты — QA-инженер. Проект: FastAPI сервис доставки еды (эндпоинты `/auth/*`, `/restaurants`, `/orders`, `/couriers`, `/admin`, `/reports`).
Напиши pytest-тесты с `TestClient`, которые:
1) создают admin и customer в БД фикстурами;
2) логин через `POST /auth/login` (form: username=email, password=...);
3) создают ресторан и блюдо, оформляют заказ, проводят статусы до `delivered` с участием курьера;
4) проверяют отчёт `/reports/top-dishes`.

Используй заголовок `Authorization: Bearer <token>`. Не используй мок БД — только реальные HTTP-вызовы к приложению с dependency override для сессии при необходимости.

## Шаблон 2 — граничные случаи предметной области

Сгенерируй тесты для граничных случаев доставки еды:
- заказ с блюдом из **другого** ресторана (ожидается 422);
- переход статуса `pending` → `delivered` напрямую (ожидается 422);
- отмена заказа клиентом в статусе `pending`;
- доступ к `/orders/{id}` чужого пользователя (403).

## Шаблон 3 — чистая бизнес-логика без HTTP

Покрой unit-тестами функции `can_transition`, `compute_order_total`, `user_may_update_status` из `app/services/order_logic.py` (pytest, без клиента).

## Шаблон 4 — негативная авторизация

Тесты: запрос без JWT к защищённому эндпоинту (401), неверный пароль (401), дубликат email при регистрации (400).
