# Code review: ИИ → проблема → исправление (Лаб. 12, задание 2)

Формат по методичке. Зафиксировано не менее пяти проблем в ходе разработки.

| Что сгенерировал ИИ / первая версия | В чём проблема | Как исправили |
|-------------------------------------|----------------|---------------|
| `user: User = Depends(CurrentUser)` где `CurrentUser = Annotated[..., Depends(get_current_user)]` | Двойной `Depends`: FastAPI воспринимал параметры неверно, `POST /orders` возвращал 422 с полями `args`/`kwargs` в query. | Заменили на `user: CurrentUser` и поставили параметр с зависимостью **до** параметров с `= Depends(get_db)`, чтобы соблюсти порядок аргументов Python. |
| `_admin: AdminUser` после `db: Session = Depends(get_db)` | В Python аргумент без значения по умолчанию не может следовать за аргументом с default → `SyntaxError`. | Переставили `_admin: AdminUser` в начало списка параметров для всех admin-роутов. |
| `Depends(AdminUser)` вместо аннотации `AdminUser` | Та же семантика двойного Depends для `Annotated`. | Использовали только `_admin: AdminUser`. |
| Роутинг заказов: потенциальная путаница `GET /orders/mine` vs `GET /orders/{id}` | При неверном порядке объявления `/{order_id}` мог перехватывать `mine` (классическая ошибка). | Сначала объявлен `GET /mine`, затем `GET /{order_id}`; `id` заказа только int. |
| Отчёт `courier-load` с `outerjoin` и фильтрами по дате на `Order` | Неверная агрегация и пустые строки для курьеров без заказов; даты по `created_at` вместо факта доставки. | Перешли на `inner join` доставленных заказов и фильтр по `delivered_at`. |
| Жёстко зашитый `SECRET_KEY` по умолчанию | Риск деплоя с известным ключом. | Для локального SQLite — значение в `app/config.py` только для dev; для Docker секреты только в gitignored `.env`, в `docker-compose.yml` — только `env_file: .env` без дублирования имён секретов в YAML. |

Дополнительно: в CI для PR-диффа дифф пишется в файл `pr.diff` (избегаем лимитов `GITHUB_ENV`). Итоговый комментарий формирует **Google Gemini** (`GEMINI_API_KEY`), а не OpenAI.
